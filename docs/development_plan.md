# Development Plan

이번 주에는 기능 구현보다 공시 데이터, 질문·Agent 동작, 평가·아키텍처를 먼저 분석하고
설계합니다. 세 작업의 결과를 통합한 뒤 Data Contract와 MVP 구현 계획을 확정합니다.

## 이번 주 병렬 작업

| 담당 | 작업 | 완료 기준 |
| --- | --- | --- |
| 팀원 1 | manifest/universe/XML 관계와 XML 3~5개 비교, 정기·거래소공시 차이, Section/Table/단위/행열/당기전기 위치, 정정 구분 조사 | 분석 문서와 Parser 출력 예시가 `docs/data_analysis/`에 정리됨 |
| 팀원 2 | 질문 범위, 대표 질문 15개, 유형 분류, 필요 문서·정보, 검색 과정, 답변 형식, 가능·불가능 범위 설계 | 질문 및 Agent 동작 설계가 `docs/agent_design/`에 정리됨 |
| 팀원 3 | Gold Q/A/Document 구조, 검색·답변 평가 기준, Agent 아키텍처, MVP, 일정, GitHub 구조, 공통 문서 통합 | 평가·아키텍처·관리 문서가 `docs/evaluation/` 및 공통 문서에 정리됨 |

## 통합 및 확정 순서

| 순서 | 단계 | 완료 기준 |
| --- | --- | --- |
| 1 | 분석·설계 산출물 작성 | 세 담당 영역의 이번 주 산출물 초안 완료 |
| 2 | 교차 검토 | XML 제약, 질문 요구사항, 평가 가능성 사이의 불일치 식별 |
| 3 | Data Contract 보완 | 세 영역의 요구사항을 `docs/data_contracts.md` Draft에 반영 |
| 4 | MVP 범위·아키텍처 확정 | 지원 질문, 필요한 데이터 흐름, 평가 기준과 모듈 경계 합의 |
| 5 | 구현 작업 배정 | 합의된 범위에 따라 기능 단위 작업과 테스트 계획을 별도 배정 |

이번 주에는 범용 Parser, 실제 Retrieval/LLM, API, HyperCLOVA X, 검색 구현을 완료 기준에
포함하지 않습니다.

## 구현 모듈에 대한 원칙

기존 `src/disclosure_agent/periodic`, `event`, `retrieval`, `agent`, `api` 디렉터리는 향후
시스템 구현을 위한 공용 모듈 구조로 유지합니다. 이 디렉터리는 특정 팀원의 소유 영역이
아니며, 이번 주 역할분담을 근거로 삭제·이동하거나 구현 책임을 고정하지 않습니다.
